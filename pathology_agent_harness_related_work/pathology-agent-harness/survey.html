Pathology agent / harness 定向调研

日期：2026-09-17；读者：计算病理熟悉、agent 新手；资源：两张 A6000 + LLM API。 本报告选取六篇主线文献和两篇工程资料，目的在于建立概念地图并找到可复现入口，而不是罗列尽可能多的名称。 各项公开状态以本次在线核查为限；没有把预印本统一认定为已发表论文。

一、最重要的判断

建议首先沿“病理科研工作流的可靠执行与评测”学习，而不是直接搭建自主诊断或大规模多智能体系统。 这是根据你的已有 WSI/MIL 经验与资源作出的选题建议，不是文献已经证明的唯一最优方向。 你可以将已熟悉的切片、特征、训练、评估代码变成可信工具，把学习重点集中到动作选择、失败反馈和结果核验。

这条主线的文献连接是：

ReAct：动作与观察如何构成循环
   ↓
PathLab：病理科研意图怎样转为工具/技能工作流
   ↓
ACP-Bench：执行成功与结论可信应如何分别核查
   ↓
AHE：有了失败证据后，怎样改进 harness 而不训练 LLM

PathNavigate 和 PathPocket 是必要的旁支：前者帮助理解 WSI 的视觉证据选择，后者帮助理解外部文献证据。 两者可贡献工具或评测维度，但不是 PathLab 的同任务直接替代品。[R1–R6]

二、不要把四类问题混成一个赛道

研究目标 典型输入 → 输出 本次代表 适合你从哪里切入
病理科研流程自动执行 分析目标、数据 → 可核验实验产物 PathLab 将已有 MIL 代码封装成工具
WSI 主动导航 巨幅切片、问题 → 选定视野与答案 PathNavigate 检查视觉预算、证据覆盖与失败
循证病理问答 病例/图像、知识库 → 带证据的回答 PathPocket 小型合规语料上的检索与引用核验
harness 评测与适应 任务、运行轨迹 → 评分或系统改动 ACP-Bench、AHE 真实失败分类、独立验证与回滚

这些工作使用不同任务、终点和分母。不能将 VQA accuracy、工作流通过率、医生读片表现、编码 pass@1 放到一张“谁最好”的排行榜。 表中的学习入口是本报告提出的应用方向；不是作者声称这些工作已可互换。[R2–R6]

三、六篇文献各自带来什么

ReAct：先看清 agent 循环

ReAct 将行动与观察接回后续决策，而不只做一次性文本输出。它是学习工具调用的基础工作，不是 2026 年病理研究中唯一充分的强 baseline。[R1]

你的阅读任务是画出一次“检查数据 → 看到错误 → 选择下一工具”的信息流。 先区分模型提出动作和 Python 执行动作，暂时不要纠结复杂框架。

PathLab：最贴近你现有科研工作的领域锚点

其核心是把研究意图连接到病理工具与可复用技能，并在执行前检查合理性。论文覆盖 12 个公共数据集和四类任务；公开声明仍是待同行评议发表后发布完整框架。[R2]

因此建议把它作为方法与需求分析的重点，而不是承诺“今天 clone 后就能复现”。 对照你的现有 pipeline，列出哪些错误能在执行前查出，哪些必须看到中间文件才能发现。 原文已经包含领域 guardrails；单纯“加一个验证 agent”不足以构成与它明确的区别。

ACP-Bench：回答可信并不意味着过程完成

论文中 41 个工作流与九个模型–harness 配置产生 369 条轨迹；严格通过为 10 条。可恢复诊断结果的子集有自己的分母，不能拿该子集的性能代表全部工作流。[R3]

你应学习的是评测分层：任务是否真正执行、产物是否对上输入、结论是否超出证据。 这是定义研究问题的工具，而不是“所有 agent 只有 2.7% 能用”的普遍结论。 原仓库目前也不是完整复现包，应把“复现其评测思想”与“复现论文原始全部轨迹”分开。

PathNavigate：WSI 中“先看哪里”的具体机制

它结合单张切片内的 surprise、空间候选筛选和问题相关重排序，以有限高倍视野支持问答。尽管题名写 training-free，小型记忆网络仍在切片内进行在线更新；surprise 不是肿瘤概率。[R4]

对你而言，更合适的起步不是立即重跑全部大模型，而是检查选出的 ROI 是否有组织学依据、是否被伪影吸引。 API 替代某个本地模型可以用于机制实验，但应明确标为改造版本，不能继续直接认领原文数字。

PathPocket：把检索证据接入病理问答

它以多模态知识结构支持病例理解、证据检索、筛选和回答。官方实现入口已公开，但权重和完整授权语料并不随代码全部提供。[R5][C5]

值得学习的是“某个结论究竟由哪个来源支持”，而不是一上来复制超大知识图谱。 检索到相关论文不等于该论文支持当前病例的具体判断；引用存在、内容支持、适用范围正确应分别检查。

AHE：自进化应当围绕可核查的改动

AHE 固定基础模型，根据运行轨迹调整 harness。其 Terminal-Bench 改进来自参与进化的任务集；另有冻结后的跨基准测试，不能把二者混写成同一种泛化证据。[R6]

你应借鉴“失败证据 → 一个可追溯改动 → 再评测”的过程，同时保留人工规则与静态经验库对照。 不要先部署全部工业级依赖；能稳定复现简单 agent 的错误以后，进化的对象才有意义。

四、这轮调研最容易误读的地方

PathLab 中工作流设置/编排的操作时间，不等于 WSI 处理、模型训练与最终研究全部在几十秒内完成。 ACP-Bench 的通过率、可恢复结果子集和风险审查子集不是同一个统计总体。 PathPocket 当前 v2 正文写超过 21,000 评测条目，摘要页曾返回另一规模数字；详见证据台账，暂不使用后者。 AHE 的公开仓库提示 Agent Debugger 只部分开源，不能将其表述为全部组件无门槛可复现。[R2][R3][R5][C6]

五、真正可执行的 baseline 链条

下面是本调研的实验建议，不是任何论文已完成的结果：

B0：固定 pipeline。 不使用 LLM，确定同一数据、同一配置能够产出正确预测和指标。

B1：简单单 agent。 固定 API 模型与工具集合，只添加决策—工具反馈循环。

B2：规则保护的 agent。 增加确定性 schema、患者身份、split、输出文件和预算检查。 它很重要：改进可能来自简单规则，而不是“智能体更聪明”。

B3：拟研究的 harness。 在 B2 上加入一种明确机制，比如基于产物依赖关系的运行时错误定位。 不要同时更换基础 LLM、视觉编码器、更多视野、更大预算和 memory，否则无法解释增益来自哪里。

之后才考虑 self-evolution：在开发任务上形成改动，冻结后盲测；比较每条新规则修复了什么、破坏了什么。

六、你的资源意味着怎样的优先级

两张 A6000 可以优先用于你已有的病理特征/模型工具；LLM 用 API 作为控制层，不必先训练大模型。 这只是架构分工建议，实际显存是否足够仍取决于模型、图像规模与并发，需要测量，不能预先保证。

为了减少不必要开销，先使用预提取特征与少量真实样本检查流程，再决定是否加入 WSI 高倍导航。 费用应同时统计 API 调用、重复上下文、重试和本地 GPU 时间，而不是只说“免训练”。

最先完成的学习产物应是一份可执行工具合同和失败日志，而不是十个角色的 agent 组织图。 具体分阶段交付见 00_learning_path.md，评测草案见 ../experiment/evaluation.md。

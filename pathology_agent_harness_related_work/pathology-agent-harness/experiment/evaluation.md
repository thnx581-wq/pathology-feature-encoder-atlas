# Evaluation v0 — DRAFT，不是已运行的 benchmark

冻结前提：确定实际任务、数据许可、病例与任务分组、LLM 版本、预算、工具集合、评分器和主指标。
冻结后记录配置哈希；变更应成为新协议版本，不能在看完测试结果后临时换指标。
以下为本项目提出的实验设计，不是六篇文献已经使用过的统一协议。

## 1. 任务范围与完成条件

首选任务为病理科研流程执行，不直接评估自主临床诊断。
有效任务应产出预定义的 config、输入清单、预测文件、独立指标和报告；必须满足身份、格式与数值一致性。
无效任务如患者跨 split 泄漏、缺标签，应按预定义策略阻止或交由人工处理，不能猜标签完成。
“正确拒绝无效任务”与“完成有效任务”分别报告，避免全部拒绝也获得高分。

## 2. 固定对照

B0 固定专家 pipeline；B1 同工具单 agent；B2 B1 + 确定性规则验证；B3 拟研究机制。
保持相同基础 LLM/版本/推理设置、病理模型、数据划分、工具权限、输出要求和最大预算。
多模型迁移是额外实验，不与主机制消融混在一起。
更换编码器或加入更多视野，应单独报告，不能归因于 harness。

## 3. 数据与任务分隔

患者/机构划分用于底层病理泛化；任务模板/故障家族划分用于 harness 泛化，两者都要记录。
开发集用于调试、更新 skill/memory；独立开发验证集用于选改动；最终盲测集只测冻结版本。
同一原始任务改写数条 prompt 不应分散到开发与测试，避免近重复泄漏。
最终测试标签和规则由只读独立 evaluator 持有，不作为 agent 的纠错反馈。
测试报告生成后不回写本轮经验库。

## 4. 建议主指标：有效任务的可靠完成率

ReliableCompletion = 满足全部预注册产物与有效性条件的有效任务数 / 全部安排执行的有效任务数。
超时、崩溃、无产物计失败；不能从分母排除。
需要并列报告：普通执行完成率，来显示“运行了但科学上无效”的差距。
该复合指标是本项目的操作性定义，不冒充现有公认标准。

## 5. 必要次指标

无效任务的正确阻止率与越界执行率；每类错误数量；可恢复故障的恢复率和额外开销。
产物身份正确率、独立复算一致率、报告引用产物的支持率，全部注明各自分母和缺失数。
总 API 输入/输出 token、工具次数、重试数、实际 wall time、本地 GPU 时间；成本含失败和重试。
费用采用实际计费或注明估计来源，不把缓存/超时条目静默丢掉。

如评测 WSI 导航，另外固定高倍视野数量/面积/分辨率，报告证据覆盖与问题表现，不能只比更大预算。
如评测 RAG，分别评估引用存在、引用支持具体陈述、适用范围、证据不足时的表现。
下游分类/生存性能采用对应任务方法；删失生存时间不强行转为普通分类标签。

## 6. 统计单位

workflow 成功率以任务/任务家族为单位，不把同一轨迹的几十个工具调用当成几十个独立样本。
同任务同种子配对比较；重复运行先在任务内汇总；置信区间按任务家族分组或层次 bootstrap。
病理预测指标的区间则按患者分组，并明确多张切片如何归并。
小型开发集合先做描述性错误分析，不凭很小的模拟例子宣称临床统计显著性。
正式统计方法在样本规模确定后预先冻结。

## 7. 故障注入与禁止事项

可用合成/副本注入：缺特征、列名错误、维度不符、旧产物、坐标单位错误、工具超时等。
保持原始数据只读；注入记录和真实故障分开；测试具体答案不暴露在 prompt、目录名或异常信息里。
预算约束用外部计数器执行；evaluator、测试标签、通过规则不可被自进化 agent 改写。
有些错误必须停止；“恢复率”不鼓励非法修改标签、删失状态或数据划分。

## 8. 保存内容

每次运行保存 run_id、模型/工具版本、配置与输入哈希、动作参数、工具状态、关键输出摘要、产物哈希和最终评分。
无需索取或存储模型私有思维链；可审计对象是实际动作、可见证据、结果及简洁决策说明。
失败运行同样保存；隐私字段脱敏并遵守授权边界。

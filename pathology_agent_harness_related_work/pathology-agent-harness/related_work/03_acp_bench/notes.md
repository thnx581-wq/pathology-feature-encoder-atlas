# ACP-Bench — 病理 harness 到底有没有完成任务

**论文：Evaluating Agentic Harness Systems for Autonomous Computational Pathology。**
阅读版本：2607.02598v1，2026 年预印本。**NOT_RUN**。

## 原文事实

研究以工作流轨迹、可恢复结果和证据/临床边界等层次评估系统。
41 个工作流、九个模型–harness 配置形成 369 条轨迹；按其正式标准只有 10 条通过。
能恢复诊断结果的 139 条轨迹是子集，不能取代总分母。[P]
官方 README 说明材料正在分阶段公开，目前应看作项目入口而非完整复现包。[C]

## 研究问题为何重要

一个系统可以讲出合理的分析路线，却没有完成工具调用、没有产物，或者结论与其实际产生的数据无关。
这正是你从“模型 AUC”转向“科研 agent”后需要新增的评价对象。

## 怎样理解它的评测思路

先问任务有没有真的执行，再问产物是不是能恢复和核验，最后问报告是否超出已有证据。[P]
这些检查分别对应过程、结果与陈述，不能把它们压成一句“回答很专业”。

教学例子：agent 返回一段“高风险患者预后差”的报告，但未产出预测 CSV。
这时报告语言不能弥补缺失的实验产物；把它计为完成会鼓励系统只写结论。
这个例子是本调研提出的，不是论文新增案例。

## 思路能否解决问题

它帮助暴露最终答案评分可能隐藏的执行失败；但基准本身不会修复 agent。[P]
本调研判断：需要区分模型能力、工具可用性、环境故障和 harness 规则的影响。
所比较的系统/模型配置不是充分交叉的随机因果实验，因此不宜把全部差异归因于某一 harness 品牌。

## 数字如何读

10/369 约为 2.7%，是对论文规定任务与严格通过条件的描述，不是自主诊断的普遍准确率。
风险富集审查子集不等于临床总体；可恢复概率或标签的子集也不能代表失败轨迹的预测表现。
生存/预后相关标签的 workflow 评测不应自动理解成已经完成全部删失生存统计。[P]

## 技术栈与贡献位置

这是工作流基准与评测设计工作，而不是新的 WSI 特征提取器。[P]
你应学习任务规范、轨迹归档、产物关联与分母定义，不应期待下载一个“ACP 分类模型”。

## 最小复现计划（建议，未执行）

先用自己固定 pipeline 的几类已知错误验证评分器：无输出、旧输出、错误 ID、错误指标、超时。
将“有效任务完成”和“无效任务正确拒绝”分别计分。
保持真值规则只读，要求另一进程独立复算指标；LLM 不得修改评分标准。

这属于借鉴评测方法，不能宣称已复现论文原始 369 条轨迹。
原始数据、评分材料、完整流程未来发布后还需逐项核对。

## baseline 时效性与研究启发

它是本次最贴近 pathology harness 的新近参照之一，但不是穷尽检索结论。
你的工作必须说明超越“加一些日志”在哪里：例如未见故障的定位、合理终止与回退，而不只是展示成功案例。

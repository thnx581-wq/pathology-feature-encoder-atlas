# 学习路线：以可检查的产物作为阶段门槛

这是建议的四阶段学习安排，可按自己的进度推进；“周”仅用于规划，不是对研究完成时间的承诺。
你已熟悉的病理知识不必重学，重点补充 agent 的软件接口、执行反馈与评测。

## 阶段 1（可安排为第一周）：只理解一个循环

阅读：基础概念、ReAct 笔记、Building effective agents。
学习：JSON、函数入参/返回值、异常、白名单工具、状态与日志。

产物：三个工具的合同——`inspect_dataset`、`validate_patient_split`、`summarize_artifacts`。
先不用 API；写几条固定动作模拟模型选择，就能检查运行系统是否拒绝非法顺序。

**过关条件**：能解释“模型返回调用请求”与“工具真的执行了”的区别；缺文件时不会假装验证成功。

## 阶段 2（第二周）：接一个 agent，不搭多 agent

阅读：PathLab 与长任务 harness 工程笔记。
把一个已跑通的固定 MIL 流程封装为少量工具；保存结构化输入、输出与状态。
再接当前有权限调用的 LLM API，使用该提供商当前的官方工具调用说明；本包不固定某家会过期的 SDK 语法。

产物：B0 固定流程和 B1 简单 agent 的同任务日志，固定模型版本与调用预算。

**过关条件**：从日志能还原实际调用；能检查预测属于正确患者与 split；API 超时后不会误报完成。

## 阶段 3（第三周）：先会评价，再讨论创新

阅读：ACP-Bench；按兴趣选读 PathNavigate 或 PathPocket。
开发一组小型故障任务：缺文件、错误列名、特征维度不符、患者跨 split 重叠、旧预测文件、工具超时。
这些是教学/开发用例；不要将人工设计的小集合称为已验证通用 benchmark。

产物：B2 规则保护版本、错误分类表、评测草案冻结记录。
每个失败写清楚“观察到什么、哪个规则发现、合理终止状态是什么”。

**过关条件**：安全拒绝与真实完成分开统计；知道哪些错误不能通过猜标签或换任务来修复。

## 阶段 4（第四周及以后）：受控改进与研究假设

阅读：AHE。先用人工修复一条明确规则，再让模型提出候选规则，比较二者。
限制每轮改动范围、禁止改评分器、保留 diff，使用独立开发验证任务检查回退。
正式测试前冻结 prompt、工具、memory、预算和规则；测试失败不得再写回本轮训练经验。

产物：一个明确机制、一个公平 baseline 链、一个未见任务集，以及能够承认无效/回退的报告。

**过关条件**：能证明不是仅因为多花 token、多看 patch、更换基础模型或吸收测试标签才变好。
通过后再决定是否需要多智能体或更大的知识库。

## 第一个且唯一的起步练习

在 `examples/tool_contract.example.json` 基础上，自己实现 `validate_patient_split`：
输入合成患者清单和 train/validation/test 归属；输出 `passed/blocked/error`、重叠患者数、原因。
准备“完全不重叠、存在重叠、缺少 patient_id”三种合成输入，并确认后两种不会触发训练。
这个练习不需要真实 WSI、显卡或付费 API，完成它即可开始理解 harness 的核心职责。

## 来源要点

文章讨论跨上下文窗口的长任务：初始环境建立、明确功能清单、增量推进、状态交接、测试与版本记录。
单纯压缩对话不能替代可靠的外部状态和完成验证。

## 与用户指定 workflow 的对应（本调研类比）

`AGENTS.md` 说明范围和规则；`handoff.md` 说明实际进度；`results.md` 保存结果；
`evaluation.md` 规定通过标准；真实产物目录说明系统究竟做了什么。
这些文件有助于连续协作，但只有接入工具执行、错误处理、预算和验证以后，才构成运行时 harness 的相应部分。

## pathology 示例

特征提取运行中断后，不应仅凭上次对话说“已经完成”就训练。
应检查具体患者有哪些特征、模型版本是否相同、文件是否完整，并从可靠检查结果恢复。
这是本报告设计的场景，不是来源已经完成的病理验证。

## 初学者最值得学的机制

把“计划做什么”“实际做了什么”“哪些检查通过”分开存储。
恢复任务时先检查当前文件，而不是把交接说明视为永远正确的数据库。

## 来源要点

文章区分预定义路径的 workflow 与模型动态决定行动的 agent，主张先使用简单可组合模式，再考虑复杂架构。
它讨论 chaining、routing、并行、编排与评价反馈等模式；不能把某一种模式自动当成研究创新。

## 本调研的 pathology 映射

“用户说二分类 → 填训练参数 → 固定执行”可以是 workflow，不需要为了命名 agent 而允许自由改代码。
只有当当前观察确实影响下一动作，而且自由度带来可验证收益时，动态规划才值得额外成本。

先写清楚一个工具的前置条件和输出，比先安装五个框架更容易定位错误。
复杂度应由任务需要驱动，而不是由术语流行程度驱动。

## 阅读任务

用自己的 MIL 项目写出一个预定义 workflow，再写出一个确实需要根据工具反馈分支的情形。
对照二者判断：到底哪个决策需要 LLM，哪个决策应该由明确规则完成？

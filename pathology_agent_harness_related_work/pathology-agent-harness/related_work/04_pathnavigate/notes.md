# PathNavigate — 有限视觉预算下的 WSI 导航

**阅读版本：2605.23559v1，2026 年预印本。NOT_RUN。**

## 原文事实

方法由 scan、search、readout 等环节组成：利用单张切片的在线记忆产生 surprise 候选，再进行空间筛选和问题相关重排序。
记忆以重构目标更新，surprise 用更新前的梯度范数；每张切片重新初始化。因此 training-free 不等于全部参数零更新，surprise 也不是病理标签。[P]

官方仓库是 `Pureeeee/PathNavigate_`，README 使用内部名称 SurpriseNav；提供推理与评估入口，仍需本地模型、特征、WSI 和问题文件。[C]

## 研究背景与问题

巨幅切片不能简单作为一幅普通图片全部交给多模态模型细看。
你应该关注的是“有限视野预算下怎样找到对问题有帮助的证据”，而不是先假定所有内容都已被观察。

## 机制拆解

作者将低倍内容的切片内 atypicality 作为候选先验，再结合问题相关检索与高倍信息回答。[P]
候选先验和最终诊断概率是两个概念。问题可以影响预算/覆盖路由，不能简单称所有导航步骤完全与问题无关。

本调研建议可视化三组坐标：原始候选、重排序保留、实际读取的高倍区域。
否则，即使答案变好，也难判断是选区策略有效，还是最后回答模型能力更强。

## 是否真正解决“找证据”

作者在 WSI 问答数据上评估整个系统。[P]
本调研判断：问答表现改善并不能单独证明 surprise 的每个高值区域都具有临床重要性。
背景碎屑、染色异常或罕见正常组织可能是需要检查的混淆因素；是否发生必须通过可视化和对照实验验证。

## 技术栈与资源注意

README 描述了 OpenSlide、CUDA/PyTorch、局部感知模型、PLIP 重排序、Qwen/vLLM 回答与可选训练集案例索引。[C]
API 替代本地回答模型能降低部分部署压力，但属于改造，需要独立命名并记录行为变化。
本次没有实测在两张 A6000 上的显存、吞吐或可同时加载模型的数量。

## 开源入口与评估警示

入口包括 `main.py`、`scripts/run_wsivqa.sh` 和 `scripts/eval_wsivqa.py`。
README 中的开放回答评估含 substring/BLEU/ROUGE，BCNB 使用字母严格匹配。[C]
仅有字符串命中未必代表医学含义正确；你设计的新任务需预先确定答案规范和人工核验范围。

## 建议的最小机制实验（未执行）

冻结同一特征和回答模型；固定高倍区域数、分辨率与 token 预算。
比较随机选区、空间均匀选区、文本相似度选区与 surprise + 重排。
另做关闭在线更新、关闭重排或关闭导航摘要的单项消融，避免同时变更多个模块。

产物应包括 ROI 坐标与尺度、实际图像、问题、回答、选择理由摘要、运行成本和失败例子。
真实原论文复现还需匹配权重、数据版本、提示词和可选案例库；仅复现选区不是完整结果复现。

## 与你的主线的关系

偏视觉算法时它比通用多 agent 组织更直接；偏科研流程执行时，它可以成为一个受限视觉工具，而非整个 harness。
新增贡献应回答预算、证据覆盖或失效鲁棒性中的具体问题，而不是把 surprise 换一个名称。

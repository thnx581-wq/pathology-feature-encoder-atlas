# ReAct — 先理解一个 agent 怎样运转

**阅读版本：2210.03629v3；ICLR 2023。本项目复现状态：NOT_RUN。**

## 原文事实

ReAct 把推理提示、行动和环境观察交替组织，使后续行动能利用外部反馈；论文研究问答/事实核查和交互环境任务。[P]
它提供了理解 agent loop 的基础，不是一套专为病理设计的安全运行系统。

## 研究背景与问题

要学习的核心差异是“一次给出答案”与“采取行动获得信息后再决定”。
在病理例子中，模型看到数据描述，并不等于已经打开特征文件验证形状。这是本报告的教学类比。
只会描述一个正确分析步骤，不代表这些步骤已经执行。

## 方法怎么理解

可以把 agent 想成一个反复调用的决策函数：输入当前任务、可用工具和之前的观察，输出下一项动作或停止。
工具结果再加入状态。这里不要求采集模型私有思维链；实际工具请求、响应和简洁决策摘要足以构成教学日志。

```text
inspect_dataset → 观察到特征目录为空
→ 检查是否允许提特征 → 调用已授权工具
→ 检查产物 → 执行下游任务或停止
```

这是拟实现的示例流程，不是 ReAct 原文的病理实验。

## 思路能否解决问题

原文支持交互式行动在所研究任务中的作用。[P]
本调研判断：它说明为什么需要反馈循环，却不保证工具参数正确、文件身份正确或临床结论有效。
如果工具把错误输入当成成功结果返回，agent 仍可能沿错误轨迹继续。

## 技术栈与创新位置

关键是 LLM 提示/决策和外部环境交互，而不是病理网络结构。[P]
教学实现可以仅用 Python、JSON 和一个有权限的 API；无需先引入复杂多 agent 框架。
第三方框架不是 ReAct 方法本身，也不能以框架名称替代实验定义。

## baseline 时效性

将它作为“相同 LLM + 相同工具 + 简单循环”的机制控制组很有用，但仅击败一个基础循环不足以说明优于当前所有 pathology agent。
最终还要加入确定性规则保护、领域工作流方法或相关视觉导航方法，取决于你的任务。

## 最小复现计划（建议，尚未执行）

先封装三个只读/受限工具，模型只从允许的动作名中选；设最大工具调用数。
在缺文件、正常输入和非法 split 三个教学场景中观察是否合理继续/停止。
保存真实事件日志，不记录模型口头宣称的“已执行”作为成功证据。

这叫 ReAct-style 机制实现，不能因此宣称复现了原文 HotpotQA 或交互环境的全部结果。

## 阅读自测

解释哪一条工具观察真正改变了下一步决策；找到一次模型说“完成”但产物未通过检查的例子。
能回答这两个问题，比记住框架术语更重要。
